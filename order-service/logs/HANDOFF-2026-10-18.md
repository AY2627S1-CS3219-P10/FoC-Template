## 8. Facts about other services (contract docs have the detail)
- **Credit (3003, `/v1`):** order uses Bearer `CREDIT_ORDER_SERVICE_TOKEN` (≥32 chars). `POST /credit-reservations {errandId,requesterId,amount 1..10M}`; `POST /credit-reservations/:errandId/adjustment {requesterId,targetAmount(absolute),idempotencyKey}`; `/release {requesterId,amount}`; `/settlement` exists but order must not call it. Reservation RESERVED → SETTLED|RELEASED (terminal). Retryable: network, 5xx, 409 `CONCURRENT_OPERATION`. Consumes `errand.completed.v1` (queue `credit-service.events`, DLQ `credit-service.events.dlq`), dedupes by eventId + payload hash.
- **User (3001, `/api`):** HS256 JWT claims `sub,sid,isAdmin`, 15 min; `GET /api/accounts/me` is the only place revocation/status is checked (order calls it each request; sometimes twice = N2 cleanup). No events.
- **Supplier (3002, `/api`):** `GET /api/suppliers` (no lookup by id; order scans); no events.
- **Web-app:** server-side proxy, no Socket.IO, no gateway.

## 10. Gotchas
- The shell cwd/path has a space; quote paths.
- Adding an enum value in Postgres: not usable inside the same transaction/migration.
- `errand.completed.v1` extra keys → credit sends it to the DLQ; correlation id goes in an AMQP header.
- Credit's `.env` / generated client may be stale locally; run `db:generate` in both services.
- The integration test harness fakes user/supplier with a small HTTP server and runs credit in-process (see `tests/integration/errands.spec.ts`); extend it rather than writing a new harness. Auth tokens in that harness are `Bearer requester|other|admin` — add a `courier` actor.
